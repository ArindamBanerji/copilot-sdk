# AE-SDK IMPL-1-3 Reconstruction Report

## 1. Executive Summary

The current repository contains a new prompt-variant evolution layer alongside the pre-existing rule-level `AgentEvolver`. The implementation appears to cover:

- IMPL-1 foundation: `VariantSpec`, `VariantStats`, `CategoryVariantStats`, `InMemoryVariantStore`, `PromptEvolverConfig`, `PromptVariantEvolver`, and exports (`copilot_sdk/evolution/variant_store.py:13`, `copilot_sdk/evolution/variant_store.py:34`, `copilot_sdk/evolution/variant_store.py:45`, `copilot_sdk/evolution/variant_store.py:58`, `copilot_sdk/evolution/prompt_evolver.py:21`, `copilot_sdk/evolution/prompt_evolver.py:51`, `copilot_sdk/evolution/__init__.py:9`, `copilot_sdk/evolution/__init__.py:19`).
- IMPL-2 category-aware UCB and AE-CONTEXT behavior: `get_variant` accepts keyword-only `category` and `context_key`, resolves category priority, uses category UCB when category stats exist, falls back to global UCB, and uses a UCB formula rather than raw success rate (`copilot_sdk/evolution/prompt_evolver.py:72`, `copilot_sdk/evolution/prompt_evolver.py:83`, `copilot_sdk/evolution/prompt_evolver.py:84`, `copilot_sdk/evolution/prompt_evolver.py:96`, `copilot_sdk/evolution/prompt_evolver.py:102`, `copilot_sdk/evolution/prompt_evolver.py:282`).
- IMPL-3 promotion, shadow result handling, hooks, and optional ledger integration: `record_shadow_result`, `check_for_promotion`, `_emit_lifecycle_event`, and hook helpers are present (`copilot_sdk/evolution/prompt_evolver.py:126`, `copilot_sdk/evolution/prompt_evolver.py:144`, `copilot_sdk/evolution/prompt_evolver.py:319`, `copilot_sdk/evolution/prompt_evolver.py:342`, `copilot_sdk/evolution/prompt_evolver.py:360`).

What appears missing:

- A dedicated SDK `config.py` or prompt-specific `promotion_gate.py` was proposed as possible future architecture, but the implemented scope places config and simple promotion in `prompt_evolver.py` (`docs/implementation_plans/ae_sdk_evolver.md:109`, `docs/implementation_plans/ae_sdk_evolver.md:111`, `docs/implementation_plans/ae_sdk_evolver.md:248`, `copilot_sdk/evolution/prompt_evolver.py:21`, `copilot_sdk/evolution/prompt_evolver.py:181`).
- `on_rejected` is configured but no rejection decision path invokes it; this matches the prompt caveat that rejection should not be faked unless rejection decisions are implemented (`copilot_sdk/evolution/prompt_evolver.py:37`, `copilot_sdk/evolution/prompt_evolver.py:181`).
- Lifecycle event names use existing SDK protocol event types (`shadow_completed`, `promoted`) rather than SOC symbolic names such as `SHADOW_RESULT`; this is protocol-compatible because `EvolutionEvent` rejects unsupported event types (`copilot_sdk/evolution/protocol.py:10`, `copilot_sdk/evolution/protocol.py:31`, `copilot_sdk/evolution/prompt_evolver.py:141`, `copilot_sdk/evolution/prompt_evolver.py:226`).
