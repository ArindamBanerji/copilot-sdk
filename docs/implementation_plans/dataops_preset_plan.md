# DataOpsPreset Implementation Plan

## 1. Executive Summary

Add `DataOpsPreset` to `compounding-scorer`.

This implementation adds a preset class, deterministic data quality / pipeline event seed data, a bootstrap calibration script, generated `dataops_bootstrap.json`, and tests.

No generic DataOps verification module is added in this block. DataOps uses fixture-backed seed outcomes and the existing `CompoundingScorer` learn path.

`CompoundingScorer` core must remain unchanged. Existing TradingPreset and PurchasingPreset behavior must remain intact.

## 2. Actual API Contract from Prompt 0

### DomainPreset

`compounding_scorer.config.DomainPreset` requires these attributes:

```python
name: str
shape: DomainShape
penalty_ratio: float
bootstrap_centroids: np.ndarray
eta_confirm: float
eta_override: float
temperature: float
```

There is no required preset-owned factorization method. `CompoundingScorer.score()` accepts a factor dictionary directly.

### DomainShape

`DomainShape` fields:

```python
n_categories: int
n_actions: int
n_factors: int
category_names: tuple[str, ...]
action_names: tuple[str, ...]
factor_names: tuple[str, ...]
```

`DomainShape` validates tuple lengths and exposes `tensor_shape` and `tensor_size`.

### PRESET_REGISTRY

Current registry format:

```python
PRESET_REGISTRY: dict[str, type] = {
    "purchasing": PurchasingPreset,
    "trading": TradingPreset,
}
```

Registry values are classes, not instances. `CompoundingScorer.from_preset()` does:

```python
preset_cls = PRESET_REGISTRY[domain]
preset = preset_cls()
```

DataOps should be added by importing `DataOpsPreset` in `compounding_scorer/presets/__init__.py` and adding `"dataops": DataOpsPreset`.

### CompoundingScorer.from_preset

Signature:

```python
CompoundingScorer.from_preset(domain: str, db_path: Optional[str] = None)
```

Behavior:

- Raises `ValueError` when `domain` is absent from `PRESET_REGISTRY`.
- Instantiates the registered preset class.
- Uses `data/{domain}.db` when `db_path` is omitted.
- Loads latest centroids from `DecisionStore` if present.
- Otherwise uses `preset.bootstrap_centroids`.
- Constructs GAE with:

```python
ProfileScorer(
    mu=centroids,
    actions=list(preset.shape.action_names),
    categories=list(preset.shape.category_names),
)
```

### CompoundingScorer.score

Signature:

```python
score(factors: dict[str, float], category: str) -> ScoreResult
```

Behavior:

- `category` must be in `preset.shape.category_names`.
- Unknown factor names raise `AssertionError`.
- Missing known factors default to `0.5`.
- Factor vector order is exactly `preset.shape.factor_names`.
- Calls GAE `score(factor_vector, category_index)`.
- Persists the decision to `DecisionStore`.

### CompoundingScorer.learn

Signature:

```python
learn(decision_id: str, actual_action: str, outcome: str = "confirmed") -> LearnResult
```

Behavior:

- Current implementation ignores the `outcome` string.
- `actual_action` must be one of `preset.shape.action_names`.
- Correctness is `actual_action == stored recommended_action`.
- For correct decisions, GAE update uses `preset.eta_confirm`.
- For incorrect decisions, GAE update uses `preset.eta_override * preset.penalty_ratio`.
- Incorrect decisions pass `gt_action_index`.
- Saves outcome and centroid checkpoint.

### Fingerprint Input Expectations

`compute_fingerprint(decisions, factor_names)` expects verified decision dicts containing:

```python
{
    "category": str,
    "factor_vector": list[float],
    "is_correct": bool,
}
```

For fewer than 5 decisions it returns insufficient-data defaults. For sufficient decisions it splits by `is_correct`, computes pooled per-factor sigma, converts sigma to normalized weights, and reports per-category precision only for categories with at least 3 decisions.

### Existing Preset Patterns

TradingPreset and PurchasingPreset establish these implementation patterns:

- Preset class imports `json`, `Path`, `numpy as np`, and `DomainShape`.
- Preset fields are exposed as read-only properties.
- `bootstrap_centroids` loads a sibling JSON file, validates shape, and falls back to a uniform `0.5` tensor.
- Calibration scripts import GAE through local `sys.path`, use `ProfileScorer(mu=..., actions=..., categories=...)`, then call `score(vector, category_index)`.
- Tests use `pytest.importorskip("gae.profile_scorer")`, temporary DB paths, direct seed JSON reads, bootstrap probability checks, and relational fingerprint assertions.

## 6. DataOpsPreset Contract

```python
name = "dataops"
```

Shape:

```text
6 categories x 5 actions x 6 factors
```

Categories:

```python
(
    "schema_change",
    "volume_anomaly",
    "quality_anomaly",
    "freshness_violation",
    "pipeline_failure",
    "transform_drift",
)
```

Actions:

```python
(
    "auto_approve",
    "investigate",
    "escalate_to_owner",
    "pause_downstream",
    "refer_to_specialist",
)
```

Factors:

```python
(
    "impact_scope",
    "source_reliability",
    "recurrence_frequency",
    "downstream_urgency",
    "data_freshness",
    "business_criticality",
)
```

Learning/calibration fields:

```python
penalty_ratio = 10.0
eta_confirm = 0.05
eta_override = 0.01
temperature = 0.1
```

`bootstrap_centroids` behavior:

- Load `compounding_scorer/presets/dataops_bootstrap.json` when present.
- Validate shape `(6, 5, 6)`.
- Fallback to uniform `0.5` tensor with shape `(6, 5, 6)` when file is missing or malformed.
- Do not fetch network data while loading the preset.

## 7. Seed Data Contract

`dataops_seed.json` must contain exactly 20 events.

Required aggregate outcomes:

- Correct: 14
- Incorrect: 6

Constraints:

- All 6 categories have at least one event.
- `action_taken` maps directly to `CompoundingScorer.learn(..., actual_action=...)`.
- All `action_taken` values must be in `preset.shape.action_names`.
- There is no `skip` action in DataOps.
- All categories must be in `preset.shape.category_names`.
- All factor keys must exactly match `preset.shape.factor_names`.
- All factor values must be in `[0, 1]`.
- Do not copy inconsistent metric summaries blindly. Compute counts from `dataops_seed.json` in tests.

Expected category counts from the provided rows are likely:

```text
pipeline_failure = 4
schema_change = 3
volume_anomaly = 3
quality_anomaly = 4
freshness_violation = 3
transform_drift = 3
```

Expected action counts from the provided rows are likely:

```text
auto_approve = 12
investigate = 3
escalate_to_owner = 2
pause_downstream = 2
refer_to_specialist = 1
```

Story-pattern constraints:

- Recurring auto-approved events with `recurrence_frequency >= 0.6` should be correct.
- First-time auto-approved events with `recurrence_frequency < 0.2` should be incorrect.
- `source_reliability` should not predict outcomes as well as `recurrence_frequency`.

Suggested event fields:

```json
{
  "event_id": "DOP-001",
  "dataset": "orders_daily",
  "category": "schema_change",
  "action_taken": "auto_approve",
  "is_correct": true,
  "factors": {
    "impact_scope": 0.25,
    "source_reliability": 0.80,
    "recurrence_frequency": 0.78,
    "downstream_urgency": 0.20,
    "data_freshness": 0.85,
    "business_criticality": 0.30
  }
}
```

## 8. Fingerprint Aha Contract

Story requires `source_reliability` to behave like noise and `recurrence_frequency` to behave like signal.

Tests should verify relational evidence:

- Recurring auto-approved events are reliably correct.
- First-time auto-approved events are incorrect.
- `recurrence_frequency` has stronger outcome separation than `source_reliability`.
- `compute_fingerprint()` does not rank `source_reliability` ahead of `recurrence_frequency` if stable.

Avoid brittle exact sigma assertions unless the seed data intentionally makes exact values deterministic.

## 9. Calibration Contract

Create:

```text
support/scripts/calibrate_dataops_bootstrap.py
```

Requirements:

- Reads `compounding_scorer/presets/dataops_seed.json`.
- Uses deterministic `SEED = 42`.
- Uses GAE `ProfileScorer` with the proven constructor/API:

```python
ProfileScorer(
    mu=centroids,
    actions=list(DataOpsPreset.shape.action_names),
    categories=list(DataOpsPreset.shape.category_names),
)
```

- Calls `score(vector, category_index)`.
- Correct action comes from seed field `action_taken`.
- Writes `compounding_scorer/presets/dataops_bootstrap.json`.
- Target mean correct-action probability: preferably `[0.49, 0.55]`.
- Tests may accept `[0.45, 0.60]`.
- Output should include enough metadata to verify:
  - `centroids`
  - `shape`
  - `mean_confidence`
  - `noise_scale`
  - `seed`
  - `pool_size`
  - `event_count`
  - `correct_count`
  - `incorrect_count`

No GAE files may be modified.

## 12. Implementation Notes and Risks

- Do not edit `CompoundingScorer` core.
- Register a class, not an instance.
- Preserve existing TradingPreset and PurchasingPreset registry entries.
- `temperature` on presets is currently metadata only; `CompoundingScorer.from_preset()` does not pass it to GAE.
- Calibration must use local GAE import strategy, not pip install.
- `action_taken` is the DataOps ground-truth action for calibration/tests.
- Fingerprint tests should use stable relational assertions.
- If seed rows differ from the expected category/action counts, tests should assert the computed JSON counts and the implementation output should report the actual counts.
