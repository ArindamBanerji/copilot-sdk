# PurchasingPreset Implementation Plan

## 1. Executive Summary

Add `PurchasingPreset` to `compounding-scorer`.

This implementation adds a preset class, deterministic seed order data, cached weather adapter, waste verification, a bootstrap calibration script, generated `purchasing_bootstrap.json`, and tests.

`CompoundingScorer` core must remain unchanged. The extension point is `PRESET_REGISTRY`, which currently registers TradingPreset. Purchasing should be independent of Trading and should be registered as a second preset key.

## 2. Actual API Contract from Prompt 0

### DomainPreset

`compounding_scorer.config.DomainPreset` requires these attributes:

```python
name: str
shape: DomainShape
penalty_ratio: float
bootstrap_centroids: np.ndarray
eta_confirm: float
eta_override: float
temperature: float
```

There is no required preset-owned factorization method. `CompoundingScorer.score()` accepts a factor dictionary directly.

### DomainShape

`DomainShape` fields:

```python
n_categories: int
n_actions: int
n_factors: int
category_names: tuple[str, ...]
action_names: tuple[str, ...]
factor_names: tuple[str, ...]
```

`DomainShape` validates tuple lengths and exposes `tensor_shape` and `tensor_size`.

### PRESET_REGISTRY

Current registry format:

```python
PRESET_REGISTRY: dict[str, type] = {
    "trading": TradingPreset,
}
```

Registry values are classes, not instances. `CompoundingScorer.from_preset()` does:

```python
preset_cls = PRESET_REGISTRY[domain]
preset = preset_cls()
```

Purchasing should be added by importing `PurchasingPreset` in `compounding_scorer/presets/__init__.py` and adding `"purchasing": PurchasingPreset`.

### CompoundingScorer.from_preset

Signature:

```python
CompoundingScorer.from_preset(domain: str, db_path: Optional[str] = None)
```

Behavior:

- Raises `ValueError` when `domain` is absent from `PRESET_REGISTRY`.
- Instantiates the registered preset class.
- Uses `data/{domain}.db` when `db_path` is omitted.
- Loads latest centroids from `DecisionStore` if present.
- Otherwise uses `preset.bootstrap_centroids`.
- Constructs GAE with:

```python
ProfileScorer(
    mu=centroids,
    actions=list(preset.shape.action_names),
    categories=list(preset.shape.category_names),
)
```

### CompoundingScorer.score

Signature:

```python
score(factors: dict[str, float], category: str) -> ScoreResult
```

Behavior:

- `category` must be in `preset.shape.category_names`.
- Unknown factor names raise `AssertionError`.
- Missing known factors default to `0.5`.
- Factor vector order is exactly `preset.shape.factor_names`.
- Calls GAE `score(factor_vector, category_index)`.
- Persists the decision to `DecisionStore`.

### CompoundingScorer.learn

Signature:

```python
learn(decision_id: str, actual_action: str, outcome: str = "confirmed") -> LearnResult
```

Behavior:

- Current implementation ignores the `outcome` string.
- `actual_action` must be one of `preset.shape.action_names`.
- Correctness is `actual_action == stored recommended_action`.
- For correct decisions, GAE update uses `preset.eta_confirm`.
- For incorrect decisions, GAE update uses `preset.eta_override * preset.penalty_ratio`.
- Incorrect decisions pass `gt_action_index`.
- Saves outcome and centroid checkpoint.

### Fingerprint Input Expectations

`compute_fingerprint(decisions, factor_names)` expects verified decision dicts containing:

```python
{
    "category": str,
    "factor_vector": list[float],
    "is_correct": bool,
}
```

For fewer than 5 decisions it returns insufficient-data defaults. For sufficient decisions it splits by `is_correct`, computes pooled per-factor sigma, converts sigma to normalized weights, and reports per-category precision only for categories with at least 3 decisions.

### Existing TradingPreset Pattern

TradingPreset establishes these implementation patterns:

- Preset class imports `json`, `Path`, `numpy as np`, and `DomainShape`.
- Preset fields are exposed as read-only properties.
- `bootstrap_centroids` loads a sibling JSON file, validates shape, and falls back to a uniform `0.5` tensor.
- Calibration scripts import GAE through local `sys.path`, use `ProfileScorer(mu=..., actions=..., categories=...)`, then call `score(vector, category_index)`.
- Tests use `pytest.importorskip("gae.profile_scorer")`, temporary DB paths, and relational fingerprint assertions.

## 7. Seed Data Contract

`purchasing_seed.json` must contain exactly 20 orders.

Required aggregate outcomes:

- Correct: 13
- Incorrect: 7

Constraints:

- All 5 categories have at least one order.
- `action_taken` maps directly to `CompoundingScorer.learn(..., actual_action=...)`.
- All `action_taken` values must be in `preset.shape.action_names`.
- All categories must be in `preset.shape.category_names`.
- All factor keys must exactly match `preset.shape.factor_names`.
- All factor values must be in `[0, 1]`.
- Do not copy an inconsistent action-count summary blindly. Compute action counts from `purchasing_seed.json` in tests. Based on the provided rows, expected counts are likely:
  - `order_as_planned = 17`
  - `order_more = 1`
  - `order_less = 1`
  - `skip = 1`
- Weekday protein correct should be `6/6`.
- Friday produce correct should be `1/5`.
- High event-day stockout pattern should be explicit. Define event-heavy rows as `event_flag >= 0.6` for the `0/3` claim.

Suggested order fields:

```json
{
  "order_id": "PUR-001",
  "item": "chicken_breast",
  "category": "protein",
  "action_taken": "order_as_planned",
  "quantity_ordered": 120,
  "quantity_remaining": 8,
  "stockout": false,
  "is_correct": true,
  "factors": {
    "expected_demand": 0.72,
    "day_of_week": 0.35,
    "weather_forecast": 0.40,
    "event_flag": 0.10,
    "historical_waste": 0.22,
    "supplier_lead_time": 0.45
  }
}
```

## 8. Fingerprint Aha Contract

Story C requires `weather_forecast` and `event_flag` to behave like blind spots/noisy factors and `historical_waste` to behave like a stronger signal.

Tests should verify relational evidence:

- Weekday protein orders are reliably correct.
- Friday produce is weak, especially with weather effects.
- Event-heavy orders with `event_flag >= 0.6` are incorrect/stockout in the seed.
- `historical_waste` has stronger outcome separation than `weather_forecast` and/or `event_flag` where stable.
- `compute_fingerprint()` assigns `historical_waste` a better useful signal than the weather/event factors if the generated data makes that stable.

Avoid brittle exact sigma assertions unless the seed data intentionally makes exact values deterministic.

## 10. Waste Verification Contract

Create:

```text
compounding_scorer/verification/waste.py
```

Function:

```python
verify_order(item, quantity_ordered, quantity_remaining, stockout, action_taken)
```

Behavior:

- `waste_pct = quantity_remaining / quantity_ordered` when `quantity_ordered > 0`, otherwise `0`.
- `waste_pct > 0.15` with `order_as_planned` or `order_more` is incorrect over-order.
- `stockout` with `order_less`, `order_as_planned`, or `skip` is incorrect under-order / should have ordered more.
- Otherwise correct.
- Default behavior has no external dependencies.

Suggested return shape:

```python
@dataclass(frozen=True)
class WasteVerificationResult:
    item: str
    quantity_ordered: float
    quantity_remaining: float
    stockout: bool
    action_taken: str
    waste_pct: float
    is_correct: bool
    reason: str
```

## 14. Implementation Notes and Risks

- Do not edit `CompoundingScorer` core.
- Register a class, not an instance.
- Preserve the existing TradingPreset registry entry and verification exports.
- `temperature` on presets is currently metadata only; `CompoundingScorer.from_preset()` does not pass it to GAE.
- Calibration must use local GAE import strategy, not pip install.
- `action_taken` is the Purchasing ground-truth action for calibration/tests.
- Weather adapter must stay cached/offline by default.
- Fingerprint tests should use stable relational assertions.
- If seed rows differ from the expected `17/1/1/1` action-count summary, tests should assert the computed JSON counts and the implementation output should report the actual counts.
