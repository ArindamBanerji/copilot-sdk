# TradingPreset Implementation Plan

## 1. Executive Summary

Add `TradingPreset` to `compounding-scorer`.

This implementation adds a preset class, deterministic seed trade data, cached price verification, a bootstrap calibration script, generated `trading_bootstrap.json`, and tests.

`CompoundingScorer` core must remain unchanged. The existing extension point is `PRESET_REGISTRY`, and `CompoundingScorer.from_preset("trading")` must work through that registry after the preset is registered.

## 2. Actual API Contract from Prompt 0

### DomainPreset

`compounding_scorer.config.DomainPreset` requires these attributes:

```python
name: str
shape: DomainShape
penalty_ratio: float
bootstrap_centroids: np.ndarray
eta_confirm: float
eta_override: float
temperature: float
```

There is no required `factor_vector()` method in the current protocol. `CompoundingScorer.score()` accepts a factor dictionary directly.

### DomainShape

`DomainShape` fields:

```python
n_categories: int
n_actions: int
n_factors: int
category_names: tuple[str, ...]
action_names: tuple[str, ...]
factor_names: tuple[str, ...]
```

`DomainShape` validates name tuple lengths against counts and exposes:

```python
tensor_shape
tensor_size
```

### PRESET_REGISTRY

Current registry:

```python
PRESET_REGISTRY: dict[str, type] = {}
```

Registry values must be classes, not instances. `CompoundingScorer.from_preset()` does:

```python
preset_cls = PRESET_REGISTRY[domain]
preset = preset_cls()
```

### CompoundingScorer.from_preset

Signature:

```python
CompoundingScorer.from_preset(domain: str, db_path: Optional[str] = None)
```

Behavior:

- Raises `ValueError` when `domain` is absent from `PRESET_REGISTRY`.
- Instantiates the registered preset class.
- Uses `data/{domain}.db` when `db_path` is omitted.
- Loads latest centroids from `DecisionStore` if present.
- Otherwise uses `preset.bootstrap_centroids`.
- Constructs GAE with:

```python
ProfileScorer(
    mu=centroids,
    actions=list(preset.shape.action_names),
    categories=list(preset.shape.category_names),
)
```

### CompoundingScorer.score

Signature:

```python
score(factors: dict[str, float], category: str) -> ScoreResult
```

Behavior:

- `category` must be one of `preset.shape.category_names`.
- Unknown factor names raise `AssertionError`.
- Missing known factors default to `0.5`.
- Factor vector order is `preset.shape.factor_names`.
- Calls GAE `score(factor_vector, category_index)`.
- Uses GAE `action_index`, `action_name`, `probabilities`, and `confidence`.
- Persists the decision.

### CompoundingScorer.learn

Signature:

```python
learn(decision_id: str, actual_action: str, outcome: str = "confirmed") -> LearnResult
```

Behavior:

- Current implementation ignores the `outcome` string.
- `actual_action` must be one of `preset.shape.action_names`.
- Correctness is `actual_action == stored recommended_action`.
- For correct decisions, GAE update uses `preset.eta_confirm`.
- For incorrect decisions, GAE update uses `preset.eta_override * preset.penalty_ratio` through temporary `eta_override`.
- Incorrect decisions pass `gt_action_index`.
- Saves outcome and centroid checkpoint.

### Fingerprint Input Expectations

`compute_fingerprint(decisions, factor_names)` expects verified decision dicts containing:

```python
{
    "category": str,
    "factor_vector": list[float],
    "is_correct": bool,
}
```

For fewer than 5 decisions it returns insufficient-data defaults. For sufficient decisions it splits by `is_correct`, computes pooled per-factor sigma, converts sigma to normalized weights, and reports per-category precision only for categories with at least 3 decisions.

```python

(
    "conviction",

    "time_horizon",
    "market_regime",
```

Learning/calibration fields:

`bootstrap_centroids` behavior:

- Do not fetch network data while loading the preset.

## 7. Seed Data Contract

`trading_seed.json` must contain exactly 20 trades.

Required aggregate outcomes:

- Correct: 11
- Incorrect: 9

Required trade fields should include at least:

```json
{
  "trade_id": "TRD-001",
  "ticker": "NVDA",
  "category": "equity_long",
  "direction": "buy",
  "entry_price": 100.0,
  "current_price": 112.0,
  "expected_action": "buy",
  "actual_action": "buy",
  "is_correct": true,
  "factors": {
    "conviction": 0.7,
    "research_depth": 0.9,
    "technical_signal": 0.8,
    "position_size": 0.4,
    "time_horizon": 0.6,
    "market_regime": 0.7
  }
}
```

Direction/action mapping:

- `buy` maps to action `buy`
- `hold` maps to action `hold`
- `sell` maps to action `sell`

Constraints:

- All factor values must be in `[0, 1]`.
- All categories must be in `TradingPreset.shape.category_names`.
- All `actual_action` and `expected_action` values must be in `TradingPreset.shape.action_names`.
- Seed defines all 5 preset categories.
- Seed observations must cover at least 4 of 5 categories.
- Equity short has 0 trades for now. Do not claim seed observations cover 5 of 5 categories unless an `equity_short` trade is added.

## 8. Fingerprint Aha Contract

Story C requires:

- `conviction` behaves like noise.
- `research_depth` behaves like signal.

Tests should verify relational evidence:

- High-research trades are much more often correct than low-research trades.
- `research_depth` is more useful than `conviction` when using seed-derived verified decisions.
- Prefer stable relational assertions:
  - high research correct rate > low research correct rate;
  - research-depth weight >= conviction weight, if stable with the generated seed;
  - research-depth interpretation is cleaner than conviction, if stable.

Avoid brittle exact sigma assertions unless the generated seed data makes exact values deterministic and intentionally part of the contract.


```python

    actions=list(TradingPreset.shape.action_names),
    categories=list(TradingPreset.shape.category_names),

```

- Does not use unsupported `centroids=` or `temperature=` constructor kwargs.
- Computes correct-action probabilities against seed trades.
- Writes:

```text

```

- Target mean correct-action probability: preferably `[0.49, 0.55]`.
- Tests may accept `[0.45, 0.60]`.
- Output should include enough metadata to verify:
  - `seed`
  - `mean_correct_probability`
  - `shape`
  - `centroids`
  - `trade_count`
  - `correct_count`
  - `incorrect_count`

No GAE files may be modified.

## 10. Price Verification Contract

Create:

```text
compounding_scorer/verification/price.py
```

Function:

```python
verify_trade(ticker, entry_price, direction, use_live=False)
```

Default behavior:

- Uses cached seed prices.
- No live API dependency for Loom.
- No network request unless `use_live=True` is explicitly implemented later.

Correctness rules:

- `buy` is correct if `current > entry`.
- `sell` is correct if `current < entry`.
- `hold` is correct if `abs(current - entry) / entry < 0.05`.
- Unknown ticker returns neutral/unknown source without network.

Recommended return shape:

```python
{
    "ticker": ticker,
    "entry_price": float(entry_price),
    "current_price": current_or_none,
    "direction": direction,
    "is_correct": bool_or_none,
    "source": "cached" | "unknown_ticker",
}
```

## 13. Implementation Notes and Risks

- Do not edit `CompoundingScorer` core for TradingPreset.
- Do not add a preset `factor_vector()` method unless future core API explicitly supports it.
- `temperature` on `TradingPreset` is currently metadata only; current `CompoundingScorer.from_preset()` does not pass it to GAE.
- Register a class, not an instance.
- Calibration script must use local GAE import strategy, not pip install.
- Price verification must remain cached/offline by default.
- `ScoreResult` lacks raw factor vector and timestamp; inspect `DecisionStore` if tests need stored vector details.
- `learn()` ignores the `outcome` string; verification strategy should produce an `actual_action`.
