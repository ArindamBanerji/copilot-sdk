## Synopsis

The Compounding Intelligence platform ships features faster than it can prove they work on real data. Five copilots, Tiers 1-4 complete, 992 Trading tests, 1,320 S2P tests — but no systematic answer to: "Which claims rest on fixture data pretending to be real?" The substantiation sprint closes this gap.

**The problem.** Purchasing's food-cost dashboard (P68) computes metrics from K3 archetype data — 50 synthetic suppliers and 500 synthetic orders generated by P64. The demo shows computed numbers derived from made-up data with no provenance label. This is a **confirmed live F-26 violation**: fixture values presented as measured facts. SOC's `threat_intel_enrichment` factor may have the same issue — it feeds the scorer invisibly, not a dashboard badge. S2P's OTIF and lead-time are labeled integration-pending by R18, but compliance hasn't been verified by audit.

**The fix.** Three workstreams run in parallel across three sessions (A: copilot-sdk, B: s2p-copilot, C: gen-ai-roi-demo) with zero repo overlap. First, read-only K3/K4 audits determine which metrics derive from fixture vs. real data — the Purchasing audit is DONE and confirmed F-26 on P68. Second, the substantiation discipline SDK (`copilot_sdk/substantiation/`) ships before P73 (the first measurement-gated Purchasing prompt), providing tiered evidence classification (T-A/T-S/T-O/T-R), a ClaimRegistry with ~18 entries for shipped features, and readiness checks enforcing the META-4 line. Third, oracle pipeline tests in Sessions B and C validate that the measurement infrastructure recovers a known injected effect from synthetic cohorts.

## §1 — Sprint Objective

Build the substantiation discipline that separates what the platform CAN prove from what it CLAIMS. Three parallel workstreams:

1. **Discipline SDK** (Session A) — tiers, registry, readiness checks, F-26 enforcement
2. **Oracle pipeline tests** (Sessions B+C) — synthetic cohort validation proving the measurement pipeline is READY
3. **K3/K4 audits** (all sessions) — per-copilot determination of whether computed metrics derive from fixture (K3) or real (K4) data

The sprint does NOT modify campaign code, scorer internals, or GraphStore protocols. It adds discipline tooling alongside shipped features.

## §9 — Substantiation Tiers Reference

| Tier | Name | Source | Can Substantiate | ██/░░ |
|---|---|---|---|---|
| T-A | Analytic | Mathematical proof | Capability existence, bounds | — |
| T-S | Scraped | Real external data | Day-zero context, ░░ claims | ░░ |
| T-O | Oracle | Synthetic cohort | Pipeline readiness | — |
| T-R | Real | Verified decisions | Customer-specific magnitude | ██ |

**META-4 line:** Synthetic (T-O) substantiates that the pipeline WORKS. Only Real (T-R) substantiates that the agent IMPROVES outcomes. Anyone who hands you a magnitude number on day one is showing you synthetic data.
