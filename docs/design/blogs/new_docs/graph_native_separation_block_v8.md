# Graph-native reasoning: read, route, or reshape

## 1. Where we stand vs. the prevalent view

The field has moved from RAG to graphs, and "graph engineering" now means two different things — both real advances, both stopping at the same line.

- **A knowledge / context graph — a *read*.** You build and traverse it: entities and relations, a cited multi-hop path. Its own best advocates say it plainly — *"a graph retrieves the answer,"* and grant that the graph stores the memory but doesn't make the call. Yet a read can only return what is *stated*, and only where there is a *precedent*. It is blindest exactly where it matters most: a newly-privileged identity issuing bulk device-management operations, device clean, *similar past cases: none* — which the security copilot scores on identity-risk geometry and escalates at high confidence anyway, today. And when the right answer is to *not* act — *"only four decisions in this regime; I won't score this trade yet"* — there is no passage to retrieve. No graph has a path for *"do less."*
- **A graph of agents / loops — an *orchestration*.** You wire and run it: agents as nodes, tasks as edges, fan-out → reduce → synthesize. Its own best advocates concede it *"buys breadth, not judgment,"* and that topology alone doesn't buy truth — a graph of loops needs frozen rules and ground-truth a human sets by hand, each run. But orchestration is a snapshot, not a memory: replay a real 2020 regime break and every run relearns from zero, while a system that keeps its geometry re-converges faster — provided the firm is different enough from the generic prior to have learned something worth keeping. The anchor a graph-of-loops rebuilds each run is, for a reshaping graph, the accumulated state itself.

And the word *loop* cuts both ways: a graph of loops routes work between agents; a reshaping loop routes a *verified outcome* back into the decision geometry. One rearranges who does the work; the other changes how the next decision is made.

Both treat the graph as **structure** — something to read or to route — so the argument becomes *"whose graph, which topology."* **That is the wrong axis.** Graph-native reasoning asks a different question: *does the graph's learned state change through verified decisions, and drive the next one?* The distinction is exact — **a read returns what is *stated*; a decision computes what is *right*, and the computation itself changes with every verified outcome.** The graph is neither read nor wired; it is **reshaped**, through one loop — enrich → decide or abstain → act → verify → evolve:

- **The decision is geometry.** The model interprets the context and assembles the inputs, but the *geometry* — not the model — chooses the action, scoring each option by its distance to the nearest prototype of a good decision *here*, learned from the firm's verified decisions. The centroid geometry learns from verified outcomes, and the per-factor noise fingerprint can show a team a truth a read or a route cannot: the factor they trust most is often not the one that predicts a correct outcome — a diagnostic learned from *your* decisions, not a generic importance score.
- **A verified outcome moves the prototype.** The state is a function of the decisions made, so the next decision reads a changed surface. A fact graph can't do this: its *provenance* records which document a fact came from; this records which *verified decision* moved the judgment, with a quality axis proving it improved rather than drifted, and replay to roll it back. It is a distinct *kind* of memory — beyond the three long-term types the standard taxonomy names, episodic (what happened), semantic (what's true), and procedural (how to act) — a fourth: *how well decisions are made, and where they are noise* [1]. One memory gets richer by ingestion; the other gets *better* through verified decisions.
- **A conservation gate.** Coverage × accuracy × verified-volume must clear a floor, or the system abstains — the frozen rule that keeps a self-improving loop from grading its own homework, moving only on *human-verified* outcomes, never on its own guess. It is also how the system governs its own authority: when a regime breaks it *reduces* its own autonomy until it re-earns trust — a move no reward-maximizer and no router can make, because neither has a notion of its own competence boundary.

And because the action is chosen by geometry rather than generated by the model, it is **consistent**: the same input draws the same recommendation, from the same reasoning, every time — regardless of who is on shift, the hour, or the load. A static rule is consistent too, and a temperature-zero model can be — but neither *learned* that consistency from your decisions, nor can show you the verified decision that shaped it and undo it. Consistency you can audit, that still compounds, is the one a read and a route can't offer.

So the anchor a graph-of-loops needs *by hand*, compounding intelligence **is** *by architecture*: the verified outcome is the update signal, the conservation law the frozen rule, both automatic and supervised — judgment **compounds** instead of being rebuilt each run. This runs end-to-end in the security copilot today; it is near-term-until-confirmed in the other domains. And because the graph *reshapes* rather than *replaces*, it sits **on top of** what a firm already runs: consume the process graph a tool like Celonis builds, add the decision layer it lacks, and the existing spend becomes more valuable, not obsolete — surfacing *which decision to change*, not executing it in the ERP.

**The one-line separation:**
> *Graph engineering builds a graph that **remembers**, or wires a graph that **routes**. Graph-native reasoning runs a graph that **decides** — and reshapes itself with every verified decision. Everyone else's graph is read or run. Ours compounds.*

## 2. The hero image

Three panels, left to right — the *same* graph, three ways to use it.

- **READ** — a knowledge graph with one path traced through it. *Retrieves the answer; grows by ingestion.* Spine word: **a lookup.**
- **ROUTE** — a diamond of agents, one job splitting into many and merging back. *Routes the work; anchors set by hand.* Spine word: **an orchestration.**
- **RESHAPE** — a graph of decision-prototypes with a loop running *decide → verify → reshape*, a curve bending upward beside it. *Decides, and reshapes itself; compounds from verified outcomes.* Spine word: **a decision loop.**

The line beneath: *Read and route are structure. Reshape is judgment — the only one that gets better the longer it runs.*

## 3. Questions that expose the gap

Each targets the difference itself — a graph you **read**, **route**, or **reshape** — tuned to where an industry pays for it.

- **Security —** *"After ten thousand triaged alerts, does your graph *decide* to escalate differently than on day one — or just retrieve nearer precedents faster? Show me the parameter that moved."*
- **The abstain question —** *"When the right answer is to *not* act — wait for one more test, pay the demurrage and leave the container at the dock, hold the card that's probably a life event — what does your graph retrieve? There is no path for 'do less.'"*
- **Trading / risk —** *"Your agents fan out and verify. Who freezes the risk limits and sets the ground-truth each run — and does that anchor *accumulate*, or do you rebuild it every morning? If a human sets it, you bought breadth, not judgment."*
- **Data operations —** *"When an analyst resolves a false positive, does that verdict move the trust score across every pipeline sharing the source — or just gate this one output? A verdict that changes no learned parameter verified once and learned nothing."*
- **Procurement —** *"Your provenance says which document a fact came from. Can it say which approved invoice moved the auto-approve boundary — and roll that decision back to show what flips?"*
- **Trading / data —** *"Your edge weight counts how many sources agree a signal fired. Does anything count how many times acting on it was *right*? Source-count is popularity; I'm asking about verified accuracy over time."*
- **Any P&L —** *"You said a graph is only as grounded as the nodes that can't be argued with. Name yours — revenue that landed, the claim that paid — and who maintains them. Ours are verified outcomes and a frozen gate, and they reshape the decision automatically."*
- **Any recurring close —** *"Run the same reconciliation on next quarter's data: is it *better* — fewer exceptions, tighter calls — or just as fast? Breadth is a snapshot; I'm asking whether it compounds."*
- **Any 24×7 desk —** *"Same alert, 2 a.m. versus 2 p.m.: same recommendation, from the same reasoning? Or does your graph's answer move with the prompt and the load?"*

## 4. The mechanism, precisely

The decision is a geometric computation, in four lines.

- **Score** — `P(a | f,c) = softmax( −‖f − μ[c,a]‖² / τ )`: the chosen action is the nearest prototype μ under L2 distance (τ = 0.1). It is *nearest-centroid distance, not reward-maximizing* — reward functions live only in the learning path, never in choosing the action.
- **Kernel** — `K(f, μ) = ‖f − μ‖²`: L2 distance — the kernel choice alone is worth 36.89 percentage points over dot product on bounded features (EXP-C1). The per-factor noise fingerprint (σ, from outcome-conditioned variance) is a *diagnostic* that surfaces which factors are signal and which are noise — including signal-confidence inversion, where the factor a team trusts most is its noisiest predictor — but does not weight the scoring kernel.
- **Update** — `μ[c,a] ← μ[c,a] + η · (f − μ[c,a])`: a confirmed decision moves the prototype toward it (η ≈ 0.05 on confirmation, smaller on override). This single line *is* the reshape — the geometry the next decision reads is literally moved by the last verified one.
- **Gate** — `α · q · V ≥ θ_min`: category coverage × rolling accuracy over the last 400 verified decisions × verified-volume must clear a floor, or the system abstains.

In the security copilot the geometry is a **6 × 4 × 6 tensor of 144 prototypes** (six categories × four actions × six factors); a live alert is scored to the nearest one, and a verified outcome nudges that single prototype — nameable, auditable back to the decision that moved it, reversible. The same base model, no retraining, moves from **71.7% to 78.9% accuracy across 1,000 verified decisions** — the lift is the compounding [3].

After a shock, re-convergence is *faster than the first calibration*: the categories that didn't break stay correct, so the disrupted ones need only re-clear ~55% accuracy rather than 85% — γ = N₁/N₂ > 1 — conditional on the firm's own deviation from the generic prior exceeding a threshold. A cold-start learner has no such shortcut, and relearns from zero.

## 5. What the compounding is worth (modeled)

To size the compounding alone — not the whole product, just the *dividend from getting better* — take a hypothetical mid-market distributor: **$5B revenue, ~$3B addressable spend.** Assume ~1% invoice leakage ($30M) and a conservative 40% incremental-capture ceiling ($12M recoverable) — every rate a CFO's to reset. Using the measured security-copilot compounding curve as the modeled shape (procurement's own curve is near-term-until-confirmed), decision quality climbs from **71.7% to 78.9% over the first 1,000 verified approvals.** Applied to the recoverable pool:

- a **static** twin, frozen at 71.7%, recovers ~**$8.6M/yr**;
- the **compounding** copilot, at 78.9%, recovers ~**$9.5M/yr**;
- the ~7-point gain is a recurring, net-new ~**$0.9M/yr** — earned with no new spend and no retraining, and widening as the decision count climbs.

That ~$0.9M is the whole point: it is the band a static system, however well-tuned on day one, structurally cannot reach. Modeled and illustrative — the shape is the claim, not the digit.

**The picture that makes it undeniable:** two lines from one starting point — a *static twin* running flat, and the *compounding copilot* curving up and away as verified decisions accumulate; the shaded gap between them is the dividend above. After a shock, the compounding line dips and re-climbs *faster* than it first rose; the static line simply resets.
