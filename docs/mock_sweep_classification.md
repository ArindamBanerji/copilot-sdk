### Counting and classification rules

The scan read Python source and followed relevant test helpers/imports without importing applications. It covered the four requested repository trees, including support/conftest files and a historical scratch test copy; it excluded `__pycache__`, `node_modules`, `.git` and `.venv`. Source selection began with the supplied regex, then included aliases such as `FakeArchiveStore`, `MemoryL5Store`, `RecordingGraphStore`, `_MockAGE`, `AsyncMock.run_query`, plain `Graph` classes and functions implementing graph protocol methods. Shared fixture scope was examined explicitly.

“Tests” counts static `def test_*` / `async def test_*` definitions, excluding fixture-decorated functions. Parameterized cases count once; helper files count zero; runtime skips, pytest discovery, inherited test methods and dynamically generated cases are not expanded. The standalone stress runner and validation helper therefore have zero pytest definitions. A scratch copy is counted as a physical file, not deduplicated runnable coverage.

A file gets **REPLACE** if a material graph-state/query claim relies on an ad hoc substitute, even if its other tests deserve KEEP. **The 1,717 definitions in REPLACE files are not 1,717 individual migration recommendations.** Preserve the unit tests explicitly identified in each row. DELETE is reserved for demonstrated circular code, not inferred authorship. No git history was accessed, so whether a person or Codex wrote a test and double together is unknown. Mock call-count assertions are legitimate for factory wiring, prohibited writes, retry budgets and dispatch; they are insufficient by themselves for a persistence claim. Overlap with the stress runner is not enough to delete boundary cases.

This is a source-level classification of the inspected snapshot, not a runtime dependency trace. Arbitrary dynamic fixture/plugin indirection cannot be proved absent by a static scan. Broad-match false positives and genuine AGE tests are retained in the tables to make their disposition explicit.

### Replacement backend and effort legend

- **PROTOCOL:** a canonical InMemoryGraphStore is acceptable for the identified data/endpoint tests, provided the exact methods are implemented and data is seeded through production writes. Do not override reads to return the expected answer. Use SQLite only when testing its own durable implementation.
- **AGE:** live PostgreSQL/AGE is required for the identified behavior. InMemoryGraphStore is **not** an acceptable replacement for Cypher, relationship direction, AGE serialization, locks/transactions, connection identity, pooling, database restart or query performance.
- **BOTH:** keep/add a canonical in-memory unit layer, plus real AGE cases for persistence, topology or backend parity. Memory alone is insufficient for those latter claims.
- Effort is an engineering estimate per file, including focused verification, assuming shared fixtures already exist. Shared fixture work and overlapping cases mean row estimates should not be added as a project commitment. KEEP requires **0h replacement effort**; separate enhancements are noted. REPLACE estimates appear in each row.

### When InMemoryGraphStore is acceptable

| Claim under test | Canonical InMemoryGraphStore acceptable? | Required companion / limit |
|---|---|---|
| Softmax, centroids, DK statistics, theta_min, thresholds, reward math | Yes | Inject explicit data; use the real scorer/calculation. No AGE needed for the math. |
| Response models, serialization, sorting, pure aggregates | Yes | Real memory writes are preferable when the test claims the response came from store state. |
| Factory arguments, DSN resolution, lazy construction, fail-closed policy | Yes, or a narrow mock | For actual connection/port/graph identity, add AGE. A constructor returning a fake says nothing about reachability. |
| Canonical protocol read/write, domain arguments and idempotency | Yes for that implementation | Parameterize the supported protocol contract against AGE too; signature conformance alone does not guarantee semantic parity. |
| Endpoint data depends on decisions/outcomes | Yes for fast application tests | Seed/write/read actual memory state; require AGE integration for backend predicates, row shapes and persistence. |
| AGE Cypher, entity joins, traversal direction and authorization filters | No | Seed real topology and execute production AGE queries. |
| Restart survival, archival visibility, durable migration, atomic rollback | No | Fresh connections/processes against disposable AGE; verify identities and relationships, not only totals. |
| Advisory locking, concurrent upserts, pools and latency | No | Independent connections/processes and a realistic real-graph workload. |
| Explicit demo/synthetic experiment or fixture generation | Yes | Keep scope/provenance clear; fixture correctness is not evidence of graph-backed production data. |

S2P's autouse fixture means a file can use an in-memory store without mentioning `FakeGraph` at all. Its custom `S2PTestGraphStore` evolution-event filtering should not become a second implementation of product semantics. Keep default unit isolation, explicitly request the real fixture in AGE cases, and ensure the autouse setup does not replace that store. Existing S2P active/shadow/live entity tests are already real and must remain.

The existing real AGE projection, topology, pool, active-copilot and graph-contract stress suites are valuable controls. Their presence reduces the amount of new infrastructure needed, but does not make the circular unit tests genuine AGE tests. Likewise, local SQLite restart tests are real tests of SQLite, not AGE.

### Tagging and running integration tests

Use `@pytest.mark.age` on the actual live cases (or `pytestmark = pytest.mark.age` for an all-live module). In mixed files, mark only the integration cases. The SDK already registers the `age` marker in [pyproject.toml](<../pyproject.toml#L36>); register it in each repository's active pytest configuration where needed.

Reuse [tests/graph/conftest.py](<../tests/graph/conftest.py>), [backend/tests/conftest.py](<../../s2p-copilot/backend/tests/conftest.py>) and [backend/tests/conftest.py](<../../gen-ai-roi-demo-v4-v50/backend/tests/conftest.py>) fixture patterns: configured test DSN, distinct test-owned graph per worker/process/test, production store adapter, and cleanup of only that test graph. Use UUID-based names to avoid graph-name collisions. Test writes should never target the canonical live `soc_graph`. Existing read-only canonical projection checks should remain read-only.

An AGE fixture must supply an actual AGE store/client, not a memory class carrying an AGE backend label. Seed valid factors/domain metadata through production writers; use low-level Cypher only for intentionally malformed/legacy topology and independent verification. Read back through a fresh connection for durability, and use the actual application lifespan for startup regressions.

For local unit-only runs, a missing AGE service may produce a documented skip. A dedicated AGE CI job should provide the database and fail when expected integration tests cannot run, rather than reporting success with all marked tests skipped. Keep `live_backend` HTTP checks distinct from store-level `age` cases.
